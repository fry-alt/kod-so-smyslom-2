# Метрика умного поиска

Цифры для питча (слайд «Было → стало») и для выбора запросов на сцену.

## Как меряем

- 10 эталонных запросов координатора — `data/demo/search_benchmark.json`. У каждого заранее отмечены 2–3 «правильных» волонтёра из 40 вымышленных анкет (`data/demo/volunteers.json`) и почему именно они.
- **hit@3** — в первой тройке есть хоть один правильный. Главная цифра для жюри.
- **Нашли из ждали** — строже: сколько правильных вообще попало в тройку (всего их 24).
- **Без AI** — ответы, где LLM не участвовала (недоступна или заглушка `fake`), поиск шёл по векторам и словам.
- Время — от запроса до ответа бэкенда, среднее.

Повторить: `make dev` (или `make up`) → `make seed` на пустой базе → `make benchmark`.
`uv run python scripts/benchmark.py --repeat 2` — каждый запрос дважды, видно, стабилен ли топ.

## Что это значит — честно

- **Поиск работает и без LLM**: правильный человек в тройке во всех 10 запросах. Модель упала — координатор всё равно получает кандидатов (с пометкой «оценка без AI»).
- Без LLM 10/10 во многом потому, что в демо-анкетах те же слова, что в запросах («керамика», «валяние», «Владикавказ»). На живых анкетах, где люди пишут по-разному, разрыв с LLM будет больше.
- **Что даёт LLM сверху.** Без неё нет фильтра по времени, региону и формату: в запросе 5 («будни днём») в тройку попала анкета 13 — по словам похожа («веду занятия»), а свободна только вечером и в выходные. Нет чипсов «Как я понял запрос» и объяснения «почему подходит» своими словами — только «совпадение по словам запроса: …». Для сцены нужна реальная LLM.
- Разбор запроса и переранжирование — два вызова LLM на запрос; время с реальной моделью — ⟨X⟩ с (заполнить).

## Запросы для сцены

Без AI каждый стабильно даёт правильную тройку (детерминированно, проверено дважды). С реальной LLM — прогнать ещё раз по `docs/DEMO_CHECKLIST.md`.

1. **«Нужен фотограф на четверг утром, разово»** — запрос из питча. Без AI сверху два правильных фотографа. С LLM чипсы покажут «фото · будни утро · разово».
2. **«Кто может в субботу помочь на инклюзивной мастерской по керамике?»** — 3 из 3, все свободны в выходные.
3. **«Во Владикавказе в субботу нужен волонтёр на кулинарный мастер-класс»** — 3 из 3, показывает регионы фонда.

Запрос вне данных: **«нужен водолаз в Осетии ночью»** — без AI у всех оценки не выше 6 из 100 и «похож по описанию анкеты», то есть явно «никто не подходит». С LLM — проверить, что оценки тоже низкие.

## Как замерить на реальной LLM

1. В `.env`: `LLM_PROVIDER=yandex` (или `gigachat`) и ключи — шаблон в `.env.example`.
2. Удалить `data/app.db` и `data/chroma/` (индекс был на эмбеддингах `fake`), `make dev`, `make seed` — анкеты получат профили и векторы от реальной модели.
3. `uv run python scripts/benchmark.py --repeat 2` → строку из вывода добавить в таблицу выше.
4. Если hit@3 ниже, чем без AI, — смотреть, какие запросы просели, и править `backend/app/llm/prompts/search_query.md` и `rerank.md`, затем снова пункт 3. Каждую попытку — строкой в таблицу.

# Питч: «Дети Марии» — единое пространство для волонтёров с умным подбором

> Регламент 5–7 минут + вопросы. 8 слайдов ≈ 1 минута каждый, демо — вживую (≈ 2 минуты), видео — запасной план.
> Ссылки — в начале `README.md`. Перед выходом — [DEMO_CHECKLIST.md](DEMO_CHECKLIST.md) и `/demo-check`.
> Цифры — из `docs/METRICS.md` (T-13), замер на проде 21 октября.

Говорят двое: **A** (бэкенд и AI) — слайды 5, 6, 7; **B** (интерфейс) — слайды 1–4 и демо, 8 — вместе.

---

## 1. Проблема

**На слайде:** «Анкета, Telegram, почта — и нигде нет волонтёра целиком».

**Говорим:**
- «Дети Марии» больше 30 лет помогают детям-сиротам, выпускникам детдомов и людям с ментальными особенностями — через творческие мастерские и сопровождение. Волонтёров много, и их становится больше.
- Сегодня волонтёр приходит через Яндекс-анкету, Telegram и почту. Координатор вручную «носит людей в базу», чтобы потом, когда понадобится, например, фотограф на разовую съёмку, — найти его там.
- Главная сложность — время: группы из интернатов приезжают **в будни утром и днём**, а работающим людям это неудобно. Подходит мало кто, и найти этих людей нужно быстро.
- Школьники откликаются ради баллов и пропадают — координатор не видит, кто действительно готов.

## 2. Пользователи

**На слайде:** два портрета.
- **Координатор фонда** — не айтишник, работает с ноутбука, ему нужно быстро найти людей под задачу.
- **Волонтёр** — студент-заочник, пенсионерка-бывший педагог, человек на удалёнке. Часто открывает всё с телефона, в Telegram.

**Говорим:** «Мы сделали два входа в одно приложение: сайт и Telegram Mini App для волонтёра, кабинет `/admin` для фонда».

## 3. Решение

**На слайде:** одна фраза + скриншот экрана «Умный поиск».
> Координатор пишет «нужен фотограф на четверг утром, разово» — и за секунды видит топ волонтёров с объяснением, почему они подходят, их обучением и контактом.

Путь волонтёра целиком: **анкета → профиль от AI → обучение с тестом → подбор → приглашение → участие и часы**.

## 4. Демо (вживую, ≈ 2 минуты) — ведёт B

Заранее открыто: вкладка `/admin` на ноутбуке (проектор), телефон с Telegram (чат с ботом очищен), вкладка с видео-запасом.

| # | Где | Что делаем | Что говорим |
|---|---|---|---|
| 1 | Telegram, [@DetiMarii_bot](https://t.me/DetiMarii_bot) | `/start` → «📝 Заполнить анкету» | «Волонтёр пришёл из канала фонда — анкета открывается прямо в Telegram» |
| 2 | Mini App, анкета | Заполнить заготовку (см. ниже) → «Отправить» | «Свободные ответы — как человек привык говорить. Время — галочками: фонду особенно нужны будни днём» |
| 3 | Mini App | Экран «Вот что мы о вас поняли» | «AI собрал профиль: навыки, интересы, подходящие роли фонда. Имя и телефон в AI не отправлялись» |
| 4 | Mini App → «Пройти обучение» | Открыть модуль, ответить на 1–2 вопроса теста | «Обучение до допуска: тексты фонда, тест генерирует AI. Координатор видит балл» (полностью не проходим — экономим время) |
| 5 | Ноутбук, `/admin` | Запрос **«Нужен фотограф на четверг утром, разово»** (≈ 8 с — пока ищет, говорим фразу) | «Координатор пишет своими словами» |
| 6 | `/admin` | Показать чипсы «Как я понял запрос» | «Система показывает, как поняла: навыки, будни утро, разово — если поняла не так, видно сразу» |
| 7 | `/admin` | Карточки кандидатов: оценка, «почему подходит», обучение, контакт | «Объяснение в одну фразу — решение всегда за человеком» |
| 8 | `/admin` → «Возможности» → «Подобрать» → «Пригласить» | Пригласить 1–2 человек | «Возможность → подбор → приглашение в один клик» |
| 9 | `/admin` | Запрос вне данных, например «нужен водолаз в Осетии ночью» (на проде у всех оценка 0 и причина «не водолаз») | «Если подходящих нет — система честно это показывает, а не выдумывает» |

**Заготовка анкеты для сцены** (вымышленная): «Я на пенсии, 20 лет вела кружок керамики, люблю работать с детьми» · навыки «керамика, лепка, фотографирую на телефон» · будни утро и день · Москва · очно · постоянно.

## 5. Как работает AI — говорит A

**На слайде:** упрощённая схема из [ARCHITECTURE.md](ARCHITECTURE.md): анкета → профиль (LLM) → векторный индекс; запрос → разбор (LLM) → фильтр по времени → поиск по смыслу → переранжирование с объяснением (LLM).

- **Модель:** YandexGPT Pro на проде, эмбеддинги Yandex. Почему: данные остаются в России, оплата в рублях. Lite пробовали — быстрее на 2 с, но точность падает, вернули Pro.
- **Где ещё AI:** профиль из свободных ответов анкеты, тест по текстам фонда, план собеседования по анкете, благодарность волонтёру по его часам.
- **Время — жёсткий фильтр, а не пожелание для модели**: галочки в анкете надёжнее любого извлечения из текста.
- **Векторы отбирают, LLM объясняет**: один вызов модели на запрос, а не на каждого кандидата.
- **Против галлюцинаций:** ответ модели — строгий JSON по схеме с проверкой и повтором; показываем, как поняли запрос; если модель недоступна — поиск работает без неё (пометка «оценка без AI»); решения о допуске и приглашении принимает человек.

## 6. Персональные данные и 152-ФЗ — говорит A

**На слайде:** таблица «что уходит в AI».

| Данные | Где | В AI и поиск по смыслу |
|---|---|---|
| Имя, контакт, Telegram ID | только наша база | **нет** |
| Ответы анкеты (навыки, интересы, время) | наша база | да — фонд считает их обезличенными |
| Заметки координатора (могут быть истории о подопечных) | только наша база | **нет** |

Согласие на обработку данных — обязательная галочка в анкете. Кандидат для модели — просто номер.

## 7. Эффект — говорит A

**На слайде:** было → стало + цифра.
- **Было:** волонтёр размазан по каналам, подбор по памяти и переписке, разовый фотограф ищется долго или не находится.
- **Стало:** всё в одном месте; запрос словами → топ кандидатов с объяснением за **5–8 секунд**.
- **Как измерили:** 10 эталонных запросов координатора по 40 вымышленным анкетам, у каждого заранее отмечены «правильные» люди → **правильный волонтёр в топ-3 в 10 из 10 запросов** (hit@3, YandexGPT Pro, каждый запрос дважды — 20 из 20); из 24 «правильных» людей в тройку попадают 23. Если модель недоступна — тоже 10 из 10 по смыслу анкеты, но без фильтра по времени и объяснений. Подробно — `docs/METRICS.md`.
- **Что фонд получает завтра:** одна ссылка для волонтёров (сайт + бот), кабинет с базой и поиском, обучение до допуска, учёт часов.

## 8. Внедрение и дорожная карта — вместе

**Как фонд заберёт проект:**
- Открытый код, понятный README; один сервер с Docker — ≈ 500 ₽/мес за VPS + LLM по факту. Оценка для YandexGPT Pro (0,80 ₽ за 1000 токенов, тариф Yandex AI Studio на июль 2026): поиск ≈ 5 тыс. токенов ≈ 4 ₽, анкета с профилем и тестом ≈ 5 тыс. токенов ≈ 4 ₽ → 200 поисков и 100 новых анкет в месяц ≈ **1,2 тыс. ₽/мес**.
- Каждое изменение в `main` само выкладывается на сервер; доделывать могут волонтёры-разработчики.

**Почему такой стек (фонд просил обосновать)** — коротко из [ARCHITECTURE.md](ARCHITECTURE.md#почему-этот-стек-фонд-просит-обосновать):
- Python/FastAPI, React — open source, простой читаемый код.
- SQLite → PostgreSQL сменой одной строки; Chroma — векторный поиск без платного сервиса.
- YandexGPT/GigaChat — данные в РФ; слой переключается на другого провайдера через настройки.
- Сайт + Telegram Mini App + «на экран Домой» — без магазинов приложений; бот — канал, которым фонд уже пользуется.
- Готовые CRM и «Добро.рф» не умеют подбор по смыслу анкеты с объяснением; «Добро.рф» оставляем для часов.

**8 блоков из описания кейса** (таблица в [CASE.md](CASE.md)): профиль, обучение, каталог возможностей, подбор, учёт участия, рабочее место фонда — **сделано**; уведомления в Telegram при смене статуса (T-15) и мотивация — часы, достижения, благодарность от AI, выгрузка часов в CSV для «Добро.рф» (T-16) — тоже **сделано**.

**Дальше:** API «Добро.рф» для часов, закрытые мероприятия и достижения, видео-курсы в обучении, роли и права сотрудников, нативные приложения из того же кода.

## Вопросы жюри — короткие ответы

- **Сколько стоит в месяц?** Сервер ≈ 500 ₽ + LLM ≈ 1,2 тыс. ₽ при 100 анкетах и 200 запросах — см. слайд 8.
- **Где хранятся данные?** На сервере фонда в России; в AI уходят только обезличенные ответы анкеты.
- **Что если модель ошибётся?** Видно, как она поняла запрос; есть объяснение для каждого кандидата; решение принимает координатор; без модели поиск всё равно работает.
- **Почему не готовая CRM?** Нет подбора по смыслу и объяснения «почему подходит»; анкету, обучение и Mini App всё равно пришлось бы делать.
- **Как фонд будет это поддерживать?** Docker на любом сервере, автоматическая выкладка, простой код; README и заметки в `docs/changes/` для следующих разработчиков.
- **Сколько волонтёров выдержит?** Сотни–тысячи анкет: поиск по смыслу локальный (Chroma), один вызов LLM на запрос.

# Как запустить

Всё работает без ключей и без сети: по умолчанию LLM-провайдер — `fake` (детерминированная заглушка).
Настоящий LLM подключается одной переменной в `.env` (раздел 8).

## 1. Что нужно

| Инструмент | Зачем | Как поставить |
|---|---|---|
| [uv](https://docs.astral.sh/uv/) | Python 3.12 и зависимости бэкенда, бота, Streamlit | `pip install uv` или инструкция на сайте |
| Node.js 22+ | сборка фронтенда (Vite) | nodejs.org |
| GNU make | короткие команды из `Makefile` | macOS/Linux — уже есть; Windows: `winget install ezwinports.make` |
| Docker Desktop | только для варианта «всё в Docker» | docker.com |

**Windows:** команды `make` запускайте из **Git Bash**. В PowerShell не работают heredoc и `bash`-скрипты.

## 2. Первый запуск

```bash
git clone https://github.com/fry-alt/kod-so-smyslom-2.git
cd kod-so-smyslom-2
make setup
```

`make setup` делает четыре вещи:
1. `uv sync` — ставит Python-зависимости (группы `dev`, `bot`, `web`);
2. `npm install` в `miniapp/`;
3. копирует `.env.example` → `.env` (если `.env` ещё нет) и дописывает в него случайный `SERVICE_KEY`;
4. включает git-хуки (`.githooks/commit-msg`).

### Обязательно поправьте `.env`

| Переменная | Что поставить для проверки | Почему |
|---|---|---|
| `COORDINATOR_CODE` | например `1111` | Код фонда для регистрации координатора. **Пустой — зарегистрироваться координатором нельзя**, а без координатора кабинет `/admin` не открыть. Потом код меняется в кабинете («Настройки»). |
| `MAIL_LOG_CODES` | оставить `true` | Почта не настроена, поэтому 6-значный код подтверждения **печатается в лог бэкенда**. `false` — регистрация сразу, без кода. |
| `SERVICE_KEY` | не трогать | Его дописал `make setup`. С ним `make seed`, `make ingest`, `make smoke` и бот ходят в API с правами координатора. |

Остальные переменные описаны в `.env.example`: у каждой есть комментарий. Для проверки их можно не трогать.

## 3. Вариант А: локально, без Docker (удобнее для разработки)

Три терминала (Git Bash), все из корня репозитория:

```bash
make dev            # 1: бэкенд FastAPI с автоперезагрузкой → http://localhost:8000/docs (Swagger)
```
```bash
make dev-miniapp    # 2: сайт на Vite → http://localhost:5173 (запросы /api/* проксируются на :8000, вебсокеты тоже)
```
```bash
make seed           # 3: демо-данные (после того как бэкенд поднялся)
```

Что происходит при старте бэкенда (`backend/app/main.py`, функция `lifespan`):
- создаются таблицы SQLite в `data/app.db` (`init_db`);
- в фоне загружаются документы фонда из `data/demo` и `data/training` в базу знаний Chroma
  (`autoload_documents`, только новые и изменённые файлы — сверяет хеш);
- в фоне индексируются волонтёры, которых ещё нет в векторном индексе (`index_missing`).

Дополнительно (необязательно):
```bash
make dev-bot        # Telegram-бот — нужен TELEGRAM_BOT_TOKEN в .env
make dev-web        # Streamlit-демо из шаблона → http://localhost:8501
```

## 4. Вариант Б: всё в Docker

```bash
make up             # собрать и поднять backend :8000, miniapp :8080, Streamlit :8501, бот (если есть токен)
make seed           # демо-данные
make logs           # логи всех контейнеров (здесь же код подтверждения почты)
make down           # остановить
```

Сайт в Docker — **http://localhost:8080**, а не 5173. Внутри контейнера `miniapp` работает Caddy:
он отдаёт собранный фронт и проксирует `/api/*` на бэкенд (`miniapp/Caddyfile`).
SQLite, Chroma и загруженные файлы лежат в `./data` (это volume) и переживают пересборку.

## 5. Демо-данные

```bash
make seed           # 40 анкет, 8 будущих занятий, история (прошедшие занятия, отклики, собеседования, статусы)
make ingest         # (необязательно) загрузить документы фонда в базу знаний вручную — обычно бэкенд делает это сам
```

- `make seed` грузит анкеты **только в пустую базу**. Тогда id волонтёра совпадает с номером анкеты
  в `data/demo/volunteers.json`, и эталонные запросы бенчмарка указывают на нужных людей.
  Начать заново: остановить бэкенд, удалить `data/app.db` и папку `data/chroma`, запустить снова.
- Даты истории считаются от сегодняшнего дня, поэтому «Сводка» в кабинете живая в любой день.
- Скрипт ходит в API по HTTP с заголовком `X-Service-Key` из `.env`. Если запускаете его не через make,
  передайте ключ сами: `SERVICE_KEY=... uv run python scripts/seed.py`.
- Демо-анкеты без аккаунтов: войти «за них» нельзя. Чтобы пройти путь волонтёра, зарегистрируйте нового.

## 6. Учётные записи для проверки

Аккаунты создаются через сайт, `/login`.

| Роль | Как создать |
|---|---|
| Координатор | `/login` → «Регистрация» → «Я координатор» → имя, почта (любая, письма не уходят), пароль, **код фонда** из `COORDINATOR_CODE` |
| Волонтёр | `/login` → «Регистрация» → «Я волонтёр» → имя, почта, пароль |

После формы появится поле для 6-значного кода. Код в терминале `make dev` (или в `make logs`):
```
WARNING | app.services.mail | Письмо (почта не настроена) → you@example.com
  123456 — код подтверждения почты
```
Удобно держать координатора и волонтёра в разных окнах: одно обычное, второе инкогнито.
Вход хранится в `localStorage` браузера.

## 7. Проверки качества

```bash
make test           # pytest: 277 тестов на провайдере fake, без сети и ключей
make lint           # ruff check + ruff format --check + tsc (типы фронта)
make smoke          # smoke-тест живого бэкенда: /health, /chat, загрузка документа и вопрос по нему
make benchmark      # метрика умного поиска hit@3 по 10 эталонным запросам (после make seed на пустой базе)
```

Те же lint, тесты и smoke гоняет CI на каждый PR (`.github/workflows/ci.yml`), плюс сборку фронта.
Помощник «Спросить о фонде» на реальной модели проверяется скриптами `scripts/rag_check.py`
(10 типовых вопросов) и `scripts/chat_check.py` (уточнения, вопросы не по теме, попытки взлома).

## 8. Настоящий LLM

В `.env` поменять провайдера и перезапустить бэкенд. Код менять не нужно.

| `LLM_PROVIDER` | Что ещё задать | Эмбеддинги |
|---|---|---|
| `fake` (по умолчанию) | ничего | «мешок слов» без сети |
| `yandex` (**на проде**) | `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`; модель `YANDEX_MODEL=yandexgpt/latest` | Yandex `text-search-doc` / `text-search-query` |
| `gigachat` | `GIGACHAT_CREDENTIALS`, `GPT2GIGA_API_KEY`, затем `docker compose --profile gigachat up -d` | `EmbeddingsGigaR` |
| `openai_compatible` | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` (OpenAI, OpenRouter, Ollama, vLLM…) | `LLM_EMBED_MODEL` |
| `anthropic` | `ANTHROPIC_API_KEY`, `uv sync --group anthropic` | локальные (`uv sync --group local-embeddings`) |

У каждого бэкенда эмбеддингов своя коллекция в Chroma (`docs_fake`, `volunteers_yandex`…). После
смены провайдера бэкенд при старте сам доиндексирует документы фонда и всех волонтёров.

Что меняется с настоящим LLM:
- профиль волонтёра — нормальные теги и фраза-резюме (на `fake` — «[fake] …»);
- умный поиск разбирает запрос (время, регион, формат) и переранжирует кандидатов с объяснением;
  на `fake` эти два шага пропускаются, поиск идёт по векторам и совпадению слов;
- тест по модулю составляет модель (на `fake` берётся готовый файл `data/training/<модуль>.quiz.json`);
- план собеседования, благодарность и ответы помощника пишет модель.

## 9. Telegram-бот и Mini App (необязательно)

1. Создать бота у [@BotFather](https://t.me/BotFather), токен положить в `TELEGRAM_BOT_TOKEN`.
2. Mini App нужен https-адрес: `make tunnel` (cloudflared, выведет `https://….trycloudflare.com`, нужен Docker).
3. Адрес вписать в `WEBAPP_URL`, перезапустить бэкенд и бота (`make dev-bot` или `docker compose up -d bot`).

С токеном бэкенд шлёт волонтёру сообщения: «прошли обучение», «вас допустили», ссылку на собеседование,
«вам написал координатор». Это работает только для анкет, заполненных из Mini App, потому что только у них
есть проверенный `telegram_id`. Без токена всё остальное работает: уведомления просто не уходят.

## 10. Фронтенд без бэкенда

```bash
cd miniapp && VITE_MOCK=1 npm run dev
```
Интерфейс работает на моках (`miniapp/src/mock.ts`) по тому же контракту. Данные живут в памяти вкладки
и в `localStorage`. Видеозвонок на моках не работает: нужен сигнальный сервер бэкенда.

## 11. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| «Регистрация координатора закрыта: код фонда ещё не задан» | В `.env` пустой `COORDINATOR_CODE`. Задать и перезапустить бэкенд |
| Не приходит код на почту | Локально письма не отправляются: код в логе бэкенда (`make dev` или `make logs`) |
| `make seed`: «В базе уже N волонтёров» | Сид только в пустую базу. Удалить `data/app.db` и `data/chroma`, или `--force` (номера в бенчмарке разъедутся) |
| `make seed` / `make ingest` → 401 или 403 | Нет `SERVICE_KEY` в окружении: запускайте через make или передайте ключ вручную |
| Кабинет `/admin` снова просит вход | Вход хранится в `localStorage`, а это другой браузер, порт или инкогнито |
| Звонок: «Нет доступа к камере» | Браузер даёт камеру только на `localhost` или `https`. По IP в локальной сети нужен `make tunnel` |
| `make` не найден / кракозябры в Windows | Запускать из Git Bash; в Makefile стоит `PYTHONUTF8=1` |
| После смены `LLM_PROVIDER` поиск без векторов | Индекс строится в фоне при старте: подождать или посмотреть предупреждения в логе |

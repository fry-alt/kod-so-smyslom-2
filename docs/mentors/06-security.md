# Доступ, персональные данные и известные ограничения

## 1. Кто что может

Проверка доступа — зависимости FastAPI в `backend/app/api/auth.py`. Логика сервисов про права не знает.

| Зависимость | Кого пускает |
|---|---|
| `current_account` | аккаунт по `Authorization: Bearer <token>` или `None` |
| `logged_in` | любой вошедший, иначе 401 |
| `coordinator` | аккаунт с ролью `coordinator` или служебный ключ `X-Service-Key` (бот, seed, smoke), иначе 401 или 403 |
| `viewer` + `check_owner` | данные волонтёра видит **он сам** (аккаунт с этой анкетой или Telegram, из которого её заполнили) **или координатор**. Чужую анкету по номеру не открыть: 403 «Это данные другого волонтёра» |
| `verified_telegram_id` | id Telegram только при верной подписи `initData` (HMAC-SHA256 с ключом от токена бота, срок 24 ч). Неверная подпись → `None`, а не доверие |

Что именно закрыто — в таблице эндпоинтов, [03-backend.md](03-backend.md#4-все-эндпоинты). Тесты доступа — `test_access.py`.

Дополнительно:
- волонтёр может только **отменить** своё собеседование, но не отметить его прошедшим;
- в переписке каждый пишет и читает только от своего имени (`_own_side` в `api/messages.py`);
- `telegram_id` анкеты берётся только из проверенной подписи, а не из тела запроса.

## 2. Пароли, коды и ключи

| Что | Как |
|---|---|
| Пароль | PBKDF2-SHA256, 200 000 итераций, соль на каждый пароль; сравнение `hmac.compare_digest` |
| Ключ входа | `secrets.token_urlsafe(32)`; меняется при сбросе пароля, после этого на других устройствах выход |
| Код из письма | 6 цифр, в БД только sha256; 15 минут, 5 попыток, повтор не чаще раза в минуту, до 10 писем в час с IP |
| «Забыли пароль?» | одинаковый ответ, есть аккаунт или нет; письмо уходит после ответа — нельзя узнать, кто зарегистрирован |
| Неверный вход | одна ошибка на «нет такой почты» и «неверный пароль» |
| Код фонда | без него нельзя стать координатором; пустой — регистрация координатора закрыта; меняется в кабинете |
| TURN | временный логин с HMAC, секрет в браузер не уходит |
| Секреты | только в `.env` (он в `.gitignore`) и в секретах GitHub; на проде Swagger выключен (`API_DOCS=false`) |

## 3. Персональные данные (152-ФЗ)

Договорились с фондом: ответы анкеты (навыки, желания, опыт, время) считаются обезличенными, их можно отправлять
во внешний LLM. Персональные данные и истории о подопечных — нельзя.

| Данные | Где | LLM | Векторный индекс | Логи |
|---|---|---|---|---|
| Имя, контакт, `telegram_id` | SQLite `volunteer` | нет | нет | нет |
| Дата рождения, телефон, почта, Telegram | SQLite `volunteerpersonal` | нет | нет | нет |
| Почта и пароль аккаунта | SQLite `account` (пароль — хэш) | нет | нет | нет |
| Ответы анкеты, профиль | SQLite | да | да | нет |
| Заметки, итог собеседования | SQLite | нет | нет | нет |
| Переписка | SQLite | нет | нет | нет |
| Вопрос помощнику | журнал `interaction` | да, телефоны и почты замаскированы | нет | нет |
| Видео собеседования | нигде: идёт напрямую между браузерами | нет | нет | нет |

Telegram-уведомления о новом сообщении — без текста. Аватар — эмодзи, фото не загружаются.
LLM на проде — YandexGPT, данные остаются в РФ. Все демо-данные вымышленные.

Мелочи, о которых тоже подумали:
- CSV для Excel экранирует значения, похожие на формулы (`=`, `+`, `-`, `@`): защита от CSV-инъекции.
- Из текста сообщений вырезаются управляющие и bidi-символы (подмена направления текста).
- Имя загружаемого документа очищается от пути (`../`), размер файла — до 20 МБ, формат — по белому списку.
- В логи уведомлений пишется только id волонтёра и тип ошибки: адрес запроса к Telegram содержит токен.

## 4. Что открыто намеренно

| Эндпоинт | Почему |
|---|---|
| `POST /volunteers` | анкету может отправить любой, в том числе без регистрации из Mini App |
| `GET /roles`, `GET /training`, `GET /training/{id}/quiz`, `GET /opportunities` | публичная информация фонда; правильные ответы теста не отдаются |
| `GET /interviews/slots` | только занятое и свободное время, без людей |
| `POST /chat`, `POST /documents/ask`, `GET /documents` | помощник для будущих волонтёров; защищён от инъекций |
| `GET /calls/{token}`, `WS /calls/{token}/ws` | вход в звонок по случайной ссылке, как в Zoom: волонтёру не нужен аккаунт |

## 5. Известные ограничения (честно)

Это хакатонный MVP. Вот что мы сознательно оставили на потом:

| Ограничение | Последствие | Как исправить |
|---|---|---|
| Бот пересылает **любой** присланный ему файл в `POST /documents/upload` со служебным ключом (обработчик из шаблона, `bot/handlers/document.py`) | любой пользователь Telegram может добавить документ в базу знаний помощника, а через него — текст, похожий на инструкции. Помощник считает документы данными, вырезает служебные теги и проверяет ответ, но правильнее закрыть сам вход | убрать обработчик или пускать только координаторов (список `telegram_id`) |
| Роль в звонке задаётся параметром `?as=coordinator`, и комнату открывает только знание `token` | волонтёр со своей ссылкой может зайти на место координатора и «вытеснить» его. Чужие данные при этом не открываются: план и итог закрыты проверкой `coordinator` | требовать вход координатора для роли `coordinator` в WebSocket |
| Нет лимита попыток входа по паролю | возможен перебор пароля | лимит по IP и по почте, как у писем |
| Ключ входа бессрочный, хранится в `localStorage` | украденный ключ работает до смены пароля | срок жизни ключа, httpOnly-cookie |
| Комнаты звонков и лимит писем — в памяти процесса | при нескольких процессах бэкенда не сработают | Redis или БД |
| SQLite и ручная мини-миграция `NEW_COLUMNS` | хватает фонду на сотни и тысячи анкет; для роста нужен PostgreSQL | SQLModel переезжает сменой `DATABASE_URL` + Alembic |
| Опрос новых сообщений раз в 5 с вместо WebSocket | небольшая задержка и лишние запросы | WebSocket или SSE |
| Ролей сотрудников нет: все координаторы равны | любой координатор видит всё | роли и права — в дорожной карте |
| Помощник ловит грубые инъекции регулярным выражением, а тонкие — промптом и проверкой ответа | промпт-инъекцию нельзя закрыть на 100% | регулярный прогон `scripts/chat_check.py`, журнал `Interaction` |

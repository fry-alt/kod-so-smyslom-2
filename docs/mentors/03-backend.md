# Бэкенд: как устроен и что делает каждая функция

FastAPI + SQLModel (SQLite) + Chroma. Python 3.12. Код — `backend/app/`.

## 1. Слои и правила

```
HTTP-запрос
  → api/*.py         тонкая обёртка: проверка доступа (Depends), 404, перевод ошибок сервиса в HTTP-коды
  → services/*.py    вся логика; про HTTP ничего не знает, поэтому легко тестируется
  → models.py (SQLite) · rag/store.py (Chroma) · llm/client.py (LLM)
```

- **Контракт API** — `schemas.py` (pydantic). Зеркало для фронта — `miniapp/src/api.ts`. Меняются только вместе,
  в одном PR.
- **LLM вызывается только через `get_llm()`** (`llm/client.py`). У каждого вызова есть фолбэк: без LLM анкета
  сохраняется, поиск находит кандидатов, тест берётся из файла.
- **Ошибки сервисов** — свои классы исключений с текстом для человека (`SearchError`, `ParticipationError`,
  `BookingError`, `ChatError`, `AuthError`). API превращает их в 4xx с тем же текстом (`detail`), а фронт показывает его как есть.
  `LLMError`, если ничего не помогло, превращается в 502 (`main.llm_error_handler`).
- **Время** — местное московское, без часового пояса (`NaiveDatetime`): «будни утром» и «суббота» считаются по нему.
  `dashboard.local_now()` — сейчас по Москве.

## 2. Запуск приложения — `main.py`, `config.py`, `db.py`, `log.py`

| Функция | Что делает |
|---|---|
| `main.lifespan` | При старте: логирование, `init_db()`, в фоновых потоках `autoload_documents()` (документы фонда → Chroma) и `index_missing()` (волонтёры без векторов → Chroma). Потоки фоновые, чтобы `/health` отвечал сразу |
| `main.llm_error_handler` | `LLMError` → HTTP 502 с понятным текстом |
| `main` (модуль) | Swagger `/docs` включается флагом `API_DOCS` (на проде выключен), CORS из `CORS_ORIGINS`, подключение 15 роутеров |
| `config.Settings` | Все настройки из `.env` через pydantic-settings, у каждой значение по умолчанию. `get_settings()` кэширует |
| `db.get_engine` | Движок SQLAlchemy; для SQLite создаёт папку под файл |
| `db.init_db` | `create_all` плюс ручная мини-миграция: `NEW_COLUMNS` дописывает колонки, появившиеся позже (`create_all` не умеет добавлять колонки в существующие таблицы) |
| `db.get_session` | Зависимость FastAPI: сессия на запрос |
| `log.setup_logging` | Единый формат логов; логи uvicorn переводятся на него, шумные библиотеки — только WARNING |

## 5. Сервисы — каждая функция

### `services/accounts.py` — аккаунты и пароли
| Функция | Как реализована |
|---|---|
| `hash_password` | PBKDF2-SHA256 из стандартной библиотеки, 200 000 итераций, случайная соль; строка `pbkdf2$итерации$соль$хэш` |
| `check_password` | пересчитывает хэш с той же солью и сравнивает `hmac.compare_digest` (без утечки по времени) |
| `by_email`, `by_token` | поиск аккаунта; почта всегда в нижнем регистре |
| `coordinator_code` | код фонда из БД (`FundSetting`), иначе `COORDINATOR_CODE` из `.env`; пусто — регистрация координатора закрыта |
| `set_coordinator_code` | сохранить код из «Настроек» |
| `prepare` | проверка формы регистрации: почта свободна, код фонда верный (для координатора), имя не пустое → заявка **с хэшем пароля** |
| `create` | аккаунт по заявке; ключ входа `secrets.token_urlsafe(32)` |
| `register` | регистрация без письма (когда почта выключена): `create(prepare(...))` |
| `login` | одна и та же ошибка «Неверная почта или пароль» и для неизвестной почты, и для неверного пароля |
| `set_password` | новый пароль **и новый ключ входа**: на других устройствах выход |
| `link_volunteer` | первая анкета, отправленная из аккаунта волонтёра, становится его анкетой |
| `link_telegram` | вход в Mini App: связать аккаунт с анкетой из этого Telegram или дописать анкете `telegram_id` |
| `get_look`, `save_look` | оформление кабинета, по умолчанию — `Look()` |

### `services/email_codes.py` — коды подтверждения почты
| Функция | Как реализована |
|---|---|
| `_issue` | 6-значный код (`secrets.randbelow`), в БД только `sha256(почта:цель:код)`. Новый код не отменяет два прежних (письма приходят с задержкой). Повтор не чаще 60 с (429) |
| `_use` | срок 15 минут, не больше 5 попыток; верный код удаляет заявку и возвращает её |
| `_letter` | тема, текст и HTML письма (таблица с инлайн-стилями: почтовые клиенты не понимают внешний CSS) |
| `_deliver` | отправить; не ушло — удаляем заявку, чтобы человек сразу мог запросить новую |
| `start_signup`, `resend_signup`, `finish_signup` | регистрация: заявка + код → повторная отправка → верный код создаёт аккаунт |
| `request_reset`, `send_reset_letter`, `finish_reset` | сброс пароля. Ответ одинаковый, есть аккаунт или нет, а письмо уходит в фоне **после** ответа: по времени ответа нельзя узнать, кто зарегистрирован |

### `services/mail.py` — отправка писем
| Функция | Как реализована |
|---|---|
| `sign_request` | подпись AWS Signature V4 для Yandex Cloud Postbox (SES-совместимый API) своими силами, без SDK (без новой зависимости). Проверяется тестом |
| `sender` | имя отправителя в кодировке RFC 2047 (Postbox не принимает кириллицу как есть) |
| `_postbox` | `POST` в Postbox с таймаутом 15 с; ошибка → `MailError` |
| `enabled`, `configured`, `send` | Postbox настроен → письмо; нет, но `MAIL_LOG_CODES=true` → код в лог; `set_mailer` подменяет отправку в тестах |

### `services/volunteers.py` — анкета, профиль, индекс
| Функция | Как реализована |
|---|---|
| `create` | 1) сохранить анкету и личные данные; 2) `extract_profile`; 3) `volunteer_index.upsert`. Ошибка LLM на шагах 2–3 не роняет запрос: анкета уже сохранена. `telegram_id` берётся только из **проверенной** подписи Mini App, а не из тела запроса |
| `extract_profile` | промпт `profile.md` со списком ролей и ответами → `chat_json(..., Profile)`. Роли, которых нет в справочнике, отбрасываются (защита от галлюцинаций) |
| `answers_text` | ответы анкеты → текст «Умеет: …\nКогда свободен: …». Коды переводятся в слова (`AVAILABILITY`, `REGION`…). Персональных данных здесь нет: это единственный вход в LLM и индекс |
| `index_document` | `answers_text` + теги профиля — документ для векторного индекса |
| `index_metadata` | статус, занятость, регион, регулярность, время, форматы — метаданные в Chroma (пустые списки Chroma не принимает) |
| `index_missing` | при старте: волонтёры, которых нет в индексе (эмбеддинг не получился, сменили провайдера), добавляются туда. Ошибки только в лог |
| `get`, `by_telegram`, `list_all` | выборки; `by_telegram` — последняя анкета из этого Telegram |
| `update` | меняет только переданные поля, обновляет метаданные индекса, уведомляет о смене статуса |
| `add_note`, `list_notes` | заметки координатора |
| `training_score` | средний балл по лучшим попыткам каждого модуля (SQL `max` + `group by`) |
| `personal_data`, `to_out` | ответ API: анкета, личные данные, профиль, статус, балл, часы |

### `services/volunteer_index.py` — векторный индекс волонтёров
| Функция | Как реализована |
|---|---|
| `upsert` | эмбеддинг документа (`kind="doc"`) → Chroma, id = id волонтёра |
| `indexed` | кто из заданных id есть в индексе |
| `nearest` | ближайшие по смыслу **среди заданных id** (то есть уже отфильтрованных). Сначала спрашивает, кто есть в индексе: на неизвестный id Chroma падает. Сходство = `1 − косинусное расстояние` |
| `update_metadata` | обновить статус без пересчёта эмбеддинга |

### `services/search.py` — умный поиск
Подробный разбор шагов — в [04-ai.md](04-ai.md#3-умный-поиск--по-шагам).

| Функция | Как реализована |
|---|---|
| `search` | главный поток: проверить вход (запрос, роль или занятие) → `parse_query` → `filtered_pool` → `vector_similarity` → `matched_skills` → короткий список `max(TOP_K=10, limit)` → `rerank` → кандидаты (оценка LLM или фолбэк `сходство × 70 + доля навыков × 30`) → запись в журнал `Interaction` (время, сколько найдено, с AI или нет) |
| `filtered_pool` | жёсткий фильтр; никого не осталось — убираем условие по времени, потом по региону, и пишем об этом в `notes` |
| `request_text` | текст запроса для LLM и эмбеддинга: роль + занятие + слова координатора |
| `parse_query` | роль без текста → поля роли; текст → `chat_json(search_query.md, ParsedQuery)`; у занятия время, регион и формат **заменяют** разобранные из текста |
| `llm_understands` | `False` на заглушке `fake`: её «разбор» отсекал бы людей случайными фильтрами |
| `passes_filter` | статус (по умолчанию все, кроме `paused`), пересечение времени, формат, регион (онлайн-задачам регион неважен) |
| `vector_similarity` | эмбеддинг запроса (`kind="query"`) → `nearest`; эмбеддинги или индекс недоступны → пустой словарь (поиск продолжается) |
| `matched_skills` | навык «совпал», если первые 6 букв есть в анкете («керамика» ~ «керамической»), без морфологии |
| `query_words` | значимые слова запроса без стоп-слов — для фолбэка, когда LLM не разобрал запрос |
| `rerank` | один вызов LLM на запрос (не на кандидата): запрос + до 10 обезличенных анкет с id → `{id, score 0–100, reason}`. Чужие id в ответе → результат отбрасывается целиком (фолбэк) |

### `services/training.py` — обучение
| Функция | Как реализована |
|---|---|
| `load_modules`, `get_module`, `_read` | модули — markdown в `data/training/`; шапка `title`, `required`; id — имя файла; порядок — по имени |

| `fallback_quiz` | готовый тест из файла |

### `services/opportunities.py` — занятия и участие
| Функция | Как реализована |
|---|---|
| `create`, `get`, `list_all` | занятие; часовой пояс отбрасывается — хранится местное время, как написал координатор |
| `time_slot` | время начала → графа анкеты: выходные / будни утром (<12) / днём (<17) / вечером |
| `is_recommended` | «подходит вам» без LLM: формат, регион (кроме онлайн), время совпадают с анкетой, и роль подходит (`role_matches`) |
| `role_matches` | роль в профиле от AI или навык роли встречается в ответах и профиле |
| `to_out` | занятие + сколько мест занято + «подходит вам» + статус участия этого волонтёра |
| `respond` | отклик; повторный не создаёт дубль; после отказа — откликается заново |
| `cancel` | «Не смогу»: `declined`; прошедшее участие с часами отменить нельзя |
| `invite` | пригласить найденных; кто уже откликнулся или участвует — остаётся как был |
| `update_status` | только `confirmed`, `attended`, `declined`; проверка мест (`slots`); `attended` начисляет часы, снятие отметки — списывает |
| `participants`, `volunteer_history`, `participation_out` | списки участия для карточки занятия и кабинета волонтёра |

### `services/interviews.py` — видеособеседование
| Функция | Как реализована |
|---|---|
| `create` | собеседование + `token = secrets.token_urlsafe(16)`; после сохранения — ссылка в Telegram (`notify.send`), флаг `notified` |
| `free_slots` | будни 10:00–17:30, шаг 30 мин, 14 дней вперёд, не раньше чем через 2 часа; занятым считается любое пересечение с назначенными (координатор мог назначить не по сетке) |
| `upcoming` | ближайшее назначенное (опоздавшего ждём 2 часа) |
| `book` | самозапись: только после обучения, одна активная запись, время должно быть в `free_slots` |
| `get`, `by_token`, `for_volunteer`, `update_status` | выборки и смена статуса |
| `save_result` | итог перезаписывается (можно поправить); собеседование → `done`; статус волонтёра не трогаем |
| `call_link`, `invitation_text` | ссылка `WEBAPP_URL/call/<token>` и текст приглашения с датой по-русски |
| `ice_servers` | STUN и, если задан `TURN_SECRET`, TURN с временным логином по схеме coturn `--use-auth-secret`: `username = срок:deti`, `password = base64(HMAC-SHA1(секрет, username))`, срок 6 часов. Секрет в браузер не уходит |

### `api/calls.py` — сигнальный сервер звонка
| Функция | Как реализована |
|---|---|
| `info` | `GET /calls/{token}`: время, статус, `ice_servers` |
| `call_error` | понятная причина, почему войти нельзя: неверная ссылка, отменено, уже прошло |
| `signaling` | WebSocket: ждёт `join {role}` 10 с; комната `rooms[token]` на два места. Тот же участник вошёл снова — старое подключение получает `replaced` и закрывается. Пересылает `signal` (SDP, ICE) адресату, рассылает `state` (микрофон, камера), `peer-joined`, `peer-left`. Комнаты живут в памяти процесса |
| `_receive`, `_send`, `_broadcast` | приём JSON с пропуском мусора; отправка с подавлением ошибок уже отключившихся |

### `services/interview_plan.py` — AI-план собеседования
| Функция | Как реализована |
|---|---|
| `get_or_build` | сохранённый план или новый; `refresh` — заново (если LLM не ответил, остаётся старый). План хранится, чтобы вопросы не менялись во время звонка |
| `generate` | промпт `interview_plan.md`: ответы анкеты + теги профиля (без имени и заметок) → `GeneratedPlan` (1–8 вопросов, до 3 пунктов «на что обратить внимание») |
| `fallback` | без LLM: 4 базовых вопроса + правила по анкете (школьник — про баллы и регулярность; нет опыта; пенсионер — про дорогу и силы; «постоянно» — про одну группу). Такой план не сохраняется: в следующий раз снова пробуем LLM |

### `services/chat.py` — переписка

# Как брать и сдавать задачи (для людей и для Claude)

Дополняет [CLAUDE.md](../CLAUDE.md). Работаем, как в Yapp: задачи в Issues, бронь исполнителем,
ветка на задачу, заметка в `docs/changes/`, PR с `Closes #N`.

## Где что

| Что | Где |
|---|---|
| Задачи (что делать, статус, обсуждение) | [Issues](https://github.com/fry-alt/kod-so-smyslom-2/issues), номер `T-NN` в заголовке |
| Порядок работы | [Milestones](https://github.com/fry-alt/kod-so-smyslom-2/milestones): `1 · Каркас` → `2 · Умный поиск` → `3 · Обучение` → `4 · Демо` → `5 · Если успеем` |
| Кто что сделал | `docs/changes/` — одна заметка на задачу |
| Контракт API | `backend/app/schemas.py` ↔ `miniapp/src/api.ts` |

Метки: `A` — бэкенд и AI, `B` — интерфейс и деплой, `P0` — без этого нет демо, `P1` — важно, `P2` — если успеем,
`контракт` — задача меняет схемы API.

## 1. Начать сессию

```bash
git checkout main && git pull
git log --since="12 hours ago" --name-only --format="%h %an %s" -- docs/changes/
gh pr list --state open
```
Прочитай новые заметки, коротко расскажи пользователю, что сделал напарник.

## 2. Выбрать задачу

Первая открытая задача своей метки без исполнителя в самом раннем незакрытом этапе:

```bash
gh issue list --label A --state open --search "no:assignee sort:created-asc" --limit 10   # B — для напарника
```
Сначала `P0`. В Issue есть «Зависит от» — если зависимость не закрыта, бери следующую
(B может работать на моках, если зависит только от эндпоинта).

## 3. Взять задачу

```bash
gh issue edit <N> --add-assignee @me
git checkout -b a/T-05-search        # b/... для трека B
```
- Исполнитель в Issue = бронь, её сразу видят все. Задачу с чужим исполнителем не бери — спроси комментарием в Issue.
- Одна ветка — одна задача. Связанные мелочи можно одной веткой: `b/T-08-T-10-forms`, назначь себя на обе.

## 4. Решить

- Делай по разделам Issue «Что сделать» и «Готово, когда». Нашёл решение лучше — можно, опиши в PR.
- Меняешь контракт — обе стороны (`schemas.py` и `api.ts`) в этом же PR, метка `контракт`, отметь напарника.
- Нашёл новую проблему вне задачи — не чини молча, заведи Issue (`gh issue create`) с меткой и `T-NN` следующим номером.

## 5. Проверить

```bash
make lint && make test
```
И руками по «Готово, когда» из Issue (Swagger `/docs` для бэкенда, браузер для фронта).
Не пиши «готово», пока не запустил.

## 6. Сдать

1. Заметка `docs/changes/ГГГГ-ММ-ДД-<github-логин>-T-NN-<коротко>.md` по [шаблону](changes/_TEMPLATE.md) — в том же PR.
2. Коммит, пуш, PR:
   ```bash
   git push -u origin HEAD
   gh pr create --fill --body "Closes #<N>

   <1–3 предложения, подробности — в заметке>"
   ```
3. Дождись зелёного CI (`gh pr checks --watch`). Красный — чини, не мержь.
4. Squash-мерж автором: `gh pr merge --squash --delete-branch`. Issue закроется сам по `Closes #N`.
   Если PR с меткой `контракт` — сначала дождись 👍 напарника.
5. `git checkout main && git pull` — и к следующей задаче.

Всё из п. 5–6 делает команда `/finish-task`, выбор и бронь из п. 2–3 — `/take-task`.

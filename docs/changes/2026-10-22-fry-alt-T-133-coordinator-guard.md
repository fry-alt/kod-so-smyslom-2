# Кабинет фонда закрыт проверкой координатора, Swagger на проде выключен, кода 1111 больше нет

## Что изменилось
- Анкеты списком, выгрузка CSV, правка статусов и часов, заметки, все переписки, сводка, поиск,
  загрузка и удаление документов, возможности (создание, приглашения, участники, статусы)
  и собеседования (назначение, результат, план) отвечают только координатору: без входа — 401, волонтёру — 403.
  Кабинет `/admin` работает как раньше — он уже присылает `Authorization: Bearer`.
- Сторона волонтёра не изменилась: анкета, каталог возможностей, отклик, запись на собеседование, «Спросить о фонде».
- Кода фонда по умолчанию `1111` больше нет. Без `COORDINATOR_CODE` и без кода из «Настроек» регистрация
  координатора закрыта («код фонда ещё не задан»). Код из «Настроек» по-прежнему главнее.
- Бот и скрипты (`make seed`, `make ingest`, `make smoke`, `make benchmark`) ходят со служебным ключом
  `SERVICE_KEY` в заголовке `X-Service-Key` — с ним пускают туда же, куда координатора.
- Swagger `/docs`, `/redoc` и `/openapi.json` на проде выключены (`API_DOCS=false`), локально работают.

## Где в коде
- `backend/app/api/auth.py` — `coordinator()` пускает координатора или служебный ключ; `is_service()`.
- `backend/app/api/*.py` — `dependencies=[Depends(coordinator)]` на маршрутах кабинета
  (dashboard, search, case — на весь роутер).
- `backend/app/services/accounts.py` — без запасного кода; `backend/app/config.py` — `COORDINATOR_CODE` пуст
  по умолчанию, новые `SERVICE_KEY` и `API_DOCS`; `backend/app/main.py` — Swagger по `API_DOCS`.
- `bot/` — `SERVICE_KEY` из `.env` уходит в заголовке каждого запроса бота.
- `scripts/` — ключ из окружения (Makefile его экспортирует из `.env`).
- `.github/workflows/deploy.yml` — на каждой выкладке новый `SERVICE_KEY`, `API_DOCS=false`,
  необязательный секрет `COORDINATOR_CODE`.
- `Makefile` — `make setup` дописывает `SERVICE_KEY` в `.env`, если его там нет.
- Контракт API (`schemas.py` ↔ `api.ts`) не менялся.

## Как проверить
- `make test`: `backend/tests/test_access.py` — каждый закрытый маршрут без входа 401, с чужим ключом 401,
  волонтёру 403; координатор и служебный ключ проходят; пустой `SERVICE_KEY` никого не пускает;
  сторона волонтёра открыта; `API_DOCS=false` убирает Swagger. `test_auth.py` — без кода регистрация
  координатора закрыта, `1111` не подходит.
- В тестах `client` ходит со служебным ключом (как фонд), `anon` — без него.

## Что осталось и на что обратить внимание
- **Напарнику и всем локально:** запустите `make setup` ещё раз — он допишет `SERVICE_KEY` в `.env`,
  иначе `make seed` и `make ingest` получат 401. Для своего координатора задайте `COORDINATOR_CODE` в `.env`.
- **На проде:** уже зарегистрированные координаторы входят как раньше. Если код фонда в «Настройках» ни разу
  не меняли, после выкладки новых координаторов не зарегистрировать, пока не задан секрет `COORDINATOR_CODE`
  (`gh secret set COORDINATOR_CODE`) — или поменяйте код в «Настройках» на длинный случайный.
  Проверьте таблицу `account`: нет ли координаторов, которых фонд не знает.
- Через бота загрузить документ может любой, кто пишет боту, — проверка на стороне бота (трек B).
- Следующий шаг (отдельная задача): проверка владельца на маршрутах волонтёра по номеру анкеты —
  `/volunteers/{id}`, переписка, отклики, собеседования, токены звонков.

# Код фонда для координатора — 1111, меняется в кабинете («Настройки»)

## Что изменилось
- **Без кода фонда координатором не зарегистрироваться.** Раньше при пустом `COORDINATOR_CODE` код не спрашивали —
  координатором мог стать кто угодно. Теперь код нужен всегда, по умолчанию **1111**.
- **В кабинете фонда новый раздел «Настройки»** (`/admin/settings`): виден текущий код, можно задать новый
  (от 4 символов, без пробелов). Уже зарегистрированные координаторы входят как раньше.
- Смотреть и менять код может только координатор: без входа — 401, волонтёру — 403.

## Где в коде
- **Контракт (A и B, @gordeymos):** `schemas.py` — `FundCode`; `api.ts` — тип `FundCode`, `authApi.fundCode()`
  и `authApi.setFundCode()`.
- **Эндпоинты:** `GET /auth/fund-code`, `PUT /auth/fund-code` (`backend/app/api/auth.py`, зависимость `coordinator`).
- **Таблица БД:** `FundSetting` (ключ → значение) — `create_all` создаст её сама.
  Логика — `coordinator_code()` и `set_coordinator_code()` в `backend/app/services/accounts.py`.
- **Переменная окружения:** `COORDINATOR_CODE` — начальный код, пока его не сменили в кабинете; пусто — 1111.
- **Фронт:** новый `screens/admin/Settings.tsx`, пункт «Настройки» и маршрут в `App.tsx`; в моках код
  в localStorage (`mock_fund_code`), по умолчанию 1111, проверяется при регистрации координатора.

## Как проверить
- `make test` — в `backend/tests/test_auth.py`: 1111 по умолчанию, код из `.env`, смена кода в кабинете
  (старый перестаёт подходить), доступ только координатору.
- Моки: регистрация координатора без кода — «Неверный код фонда», с 1111 — кабинет. «Настройки» → новый код
  → «Сохранено», дальше регистрация только с новым кодом.

## Что осталось и на что обратить внимание
- **Сменить 1111 на проде** в «Настройках» сразу после первой регистрации координатора — 1111 легко угадать.
- Эндпоинты кабинета (поиск, база, заметки) по-прежнему открыты без входа — закрыта только страница.

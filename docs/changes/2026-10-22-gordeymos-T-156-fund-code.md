# «Настройки» в кабинете фонда открываются, даже когда код фонда ещё не задан

## Что изменилось
- После T-133 кода 1111 по умолчанию нет. Если `COORDINATOR_CODE` пустой и код не меняли в кабинете, `GET /auth/fund-code` падал с 500, а координатор видел «Не удалось загрузить настройки: Не получилось…». Теперь сервер отдаёт пустой код.
- «Настройки» при пустом коде пишут «Код ещё не задан — новые координаторы пока не могут зарегистрироваться» и дают задать код.
- Если сервер отвечает 5xx без текста (по HTTP/2 у ответа нет statusText), сайт пишет «Сервер сейчас не отвечает…» вместо общего «Не получилось».

## Где в коде
- **Контракт API:** в `backend/app/schemas.py` новая схема ответа `FundCodeOut` (`code` может быть пустым). `FundCode` с проверкой «от 4 символов» осталась только для тела PUT. Тип в `miniapp/src/api.ts` тот же (`{ code: string }`), добавлен комментарий про пустой код.
- `backend/app/api/auth.py` — GET и PUT `/auth/fund-code` отвечают `FundCodeOut`.
- `backend/tests/test_auth.py` — `test_fund_code_not_set_yet`.
- `miniapp/src/api.ts` (`httpError`), `miniapp/src/screens/admin/Settings.tsx`.

## Как проверить
- `make lint && make test` — 254 теста проходят.
- Бэкенд с пустым `COORDINATOR_CODE`, вход координатором → `/admin/settings`: видно «Код ещё не задан», код `deti2026` сохраняется, после сохранения «Сейчас: deti2026».

## Что осталось и на что обратить внимание
- Изменение контракта API — нужен просмотр fry-alt до мержа.
- На проде стоит задать код фонда в «Настройках» (или `COORDINATOR_CODE` в `.env`), иначе новые координаторы не зарегистрируются.

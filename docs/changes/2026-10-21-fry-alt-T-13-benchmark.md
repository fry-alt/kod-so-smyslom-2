# Метрика поиска hit@3 (`make benchmark`) и починка поиска на заглушке `fake`

## Что изменилось
- **Поиск на `fake` больше не врёт.** Заглушка «разбирала» каждый запрос одинаково («будни утром, Москва») и этим отсекала нужных людей: hit@3 был 5/10, сверху всегда одни и те же. Теперь на `fake` поиск не спрашивает заглушку и сразу идёт как фолбэк (векторы + слова запроса): **hit@3 10/10**, 0,1 с. **Прод сейчас на `fake`** — после выкладки демо-поиск там станет нормальным.
- `make benchmark` — прогон 10 эталонных запросов против живого бэкенда: hit@3, «нашли из ждали», среднее время, доля ответов без AI. `--repeat N` — проверить, стабилен ли топ.
- `docs/METRICS.md` — цифры, что они значат (честно: без LLM нет фильтра по времени и чипсов «Как я понял запрос»), 3 запроса для сцены + запрос вне данных, как замерить на реальной LLM.
- Тест-сторож: на демо-данных поиск без LLM должен давать hit@3 не ниже 9/10.

## Где в коде
- `backend/app/services/search.py` — `llm_understands()`: на провайдере `fake` пропускаем разбор запроса и переранжирование.
- `scripts/benchmark.py`, цель `benchmark` в `Makefile` — по образцу `scripts/seed.py`, ходит в бэкенд по HTTP (`BACKEND_URL`).
- `backend/tests/test_demo_data.py` — `test_benchmark_hit_at_3_without_llm`; `test_search.py` — тестовый провайдер теперь называется `test`, чтобы поиск с ним ходил в «LLM».
- Контракт, БД, зависимости, переменные окружения не менялись.

## Как проверить
- `make test` (99 тестов).
- `make dev` → `make seed` на пустой базе → `make benchmark` → `hit@3: 10 из 10, нашли 22 из 24`.

## Что осталось и на что обратить внимание
- **Строки с реальной LLM в `docs/METRICS.md` нет** — ключей нет ни в локальном `.env`, ни на проде (`/api/health` → `fake`). Когда появятся: шаги в разделе «Как замерить на реальной LLM», затем при необходимости — правка промптов `search_query.md` / `rerank.md`. Поэтому PR с `Refs #13`, Issue остаётся открытым.
- **@gordeymos:** в `docs/PITCH.md` можно подставить цифры: hit@3 **10 из 10** (без AI, на 40 демо-анкетах), ответ за **0,1 с** без AI; время с LLM — после замера. Сценические запросы — в `docs/METRICS.md`, запрос из питча («фотограф на четверг утром, разово») там первым.
- Совет: проверять сценические запросы через Python или браузер, а не через `curl` в Git Bash на Windows — он портит кириллицу в `-d`, и поиск выглядит сломанным (все оценки 0).

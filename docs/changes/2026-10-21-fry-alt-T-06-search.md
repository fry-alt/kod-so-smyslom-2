# Умный поиск `POST /search`: запрос словами или роль → топ кандидатов с объяснением

## Что изменилось
- Координатор пишет «нужен фотограф на четверг утром» или выбирает роль — и получает кандидатов с оценкой 0–100 и фразой «почему подходит», плюс «как система поняла запрос» (навыки, время, регион, формат, разово/постоянно).
- Время, регион и очно/онлайн — жёсткий фильтр по галочкам анкеты, а не пожелание для LLM. Волонтёры на паузе не ищутся, если явно не попросить (`statuses`). Онлайн-задачам регион неважен.
- Без LLM поиск всё равно работает: оценка по сходству анкет и совпавшим навыкам, `ai: false`. Если не разобран и сам запрос — анкеты сверяются со словами запроса («совпадение по словам запроса: фотограф»).
- Каждый поиск пишется в журнал `Interaction` (`kind="search"`) со временем ответа — для метрики.

## Где в коде
- `backend/app/services/search.py` — весь поток по шагам: `parse_query()` → `passes_filter()` → `vector_similarity()` → `rerank()` → фолбэк. `TOP_K = 20` — сколько кандидатов отдаём LLM.
- `backend/app/llm/prompts/search_query.md` (запрос → `ParsedQuery`, 3 примера), `rerank.md` (запрос + обезличенные анкеты с id → оценка и причина, 1 пример).
- `backend/app/api/search.py` — `POST /search`; ошибки: пустой запрос без роли — 400, неизвестная роль — 404, `opportunity_id` — 400 (появится в T-22).
- `backend/app/services/volunteer_index.py` — `nearest()`: ближайшие в Chroma среди заданных id.
- Роль без текста запроса не идёт в LLM — `ParsedQuery` строится из полей роли; регионы роли тоже фильтруют.
- В LLM уходят только текст запроса и анкеты из `index_document()` (без имени, контакта, `telegram_id`, заметок) — имена подставляются после.
- Контракт, таблицы БД, зависимости и переменные окружения не менялись.

## Как проверить
- `make dev`, `make seed`, в `/docs` → `POST /search` с `{"role_code": "photographer"}` — в топе фотографы 4, 24, 29; `{"role_code": "ceramics_assistant"}` — керамисты 11, 35, 23.
- `make test` — `backend/tests/test_search.py`: фильтр по времени/региону/формату/статусу, онлайн без региона, порядок от LLM, фолбэк при упавшей LLM и чужих id, фолбэк без LLM и эмбеддингов, поиск по роли, нет ПД в промпте rerank, журнал, ошибки, пустая база.

## Что осталось и на что обратить внимание
- **С реальной LLM не проверено** — локально `fake`. На `fake` текстовый запрос фильтруется верно, но ранжирование плоское (fake-профили одинаковые). Качество и hit@3 по `data/demo/search_benchmark.json` — T-13.
- `opportunity_id` — в T-22 вместе с каталогом возможностей.
- Без LLM навыки сверяются грубо, по первым 6 буквам: «своя машина» не найдёт «есть свой минивэн». С нормальными профилями (теги от LLM в индексе) это почти не мешает.

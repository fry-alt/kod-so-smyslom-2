# 40 вымышленных анкет, 10 эталонных запросов координатора и `make seed`

## Что изменилось
- Есть из кого искать: `make seed` загружает 40 анкет в пустую базу — `/admin` и поиск можно показывать на правдоподобных людях.
- Состав как в жизни: 15 студентов (в основном заочники), 10 пенсионеров, 8 на удалёнке, 4 работающих, 3 школьника. Москва и область — большинство, Ярославль и Северная Осетия — по 4. Шесть человек только онлайн. В будни днём свободны лишь 15 из 40.
- Для метрики hit@3 (T-13) — 10 эталонных запросов, у каждого 2–3 «правильных» кандидата и пояснение, почему именно они.
- В анкетах есть «ловушки»: фотограф, свободный только вечером; валяльщица не из Ярославля; монтажёр только очно. Поиск без учёта времени, региона и формата на них ошибётся.

## Где в коде
- `data/demo/volunteers.json` — анкеты в формате `VolunteerIn`. Имена и контакты вымышленные (`+7 900 000-00-NN`, `@demo_…`, `…@example.com`), `telegram_id` нет.
- `data/demo/search_benchmark.json` — `queries[]`: `query`, `expected` (номера анкет в volunteers.json с 1 = id после `make seed` на пустой базе), `why`.
- `scripts/seed.py` + цель `make seed` — шлёт анкеты в `POST /volunteers`, только стандартная библиотека. В непустую базу не грузит (иначе id разъедутся с бенчмарком), `--force` — загрузить всё равно. Адрес — `BACKEND_URL`.
- `backend/tests/test_demo_data.py`; `make seed` добавлен в README и CLAUDE.md.

## Как проверить
- `make dev`, затем `make seed` → «Загружено анкет: 40», `GET /volunteers` отдаёт 40. Повторный `make seed` честно откажется.
- `make test` — анкеты валидны, контакты вымышленные, состав и регионы, бенчмарк ссылается на существующие анкеты, через API анкеты получают id 1–40.

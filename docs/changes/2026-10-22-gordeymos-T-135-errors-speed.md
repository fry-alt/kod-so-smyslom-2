# Понятные ошибки, быстрее первая загрузка, одна шкала заголовков (аудит UX-23, 26, 27, 36, 40)

## Что изменилось
- Ошибки: вместо английского или технического текста сервера — «Не получилось. Попробуйте ещё раз или напишите координатору»; русский `detail` от сервера показывается как есть; на 404 — «Не нашли. Возможно, запись удалили» (раньше — «Эта функция на сервере ещё не готова»).
- Скорость: `telegram-web-app.js` больше не задерживает отрисовку; кабинет фонда и видеозвонок загружаются отдельными файлами, только когда их открывают (около 110 КБ кода не грузится на главной); файлы `/assets/*` браузер кеширует на год.
- Заголовки страниц везде одним шрифтом Unbounded одного размера: «Поиск», «База», «Карточка волонтёра», «Обучение», «История», остальные экраны кабинета фонда.
- `/me`: плитка «часов помощи» (было «волонтёрских часов») и «балл за обучение» больше не обрезаются на 390 px; цифры счётчиков — Onest, ноль не похож на «О».
- «Аналитика»: «12 ч» и «−13» больше не разъезжаются — `tabular-nums` остался только в таблице.

## Где в коде
- `miniapp/src/ui.tsx` — `errorText` (тексты ошибок), новый `PageTitle`.
- `miniapp/src/App.tsx` — экраны `/admin/*`, `CallScreen` и `CoordinatorPanel` через `React.lazy`; `Suspense` с `Loading` внутри шапки кабинета (меню не мигает при переходах), у панели координатора в звонке — своя граница, чтобы звонок не прятался.
- `miniapp/index.html` — `defer` у `telegram-web-app.js`. Он стоит перед скриптом приложения (`type="module"`, тоже отложенный), а отложенные скрипты выполняются по порядку — `telegram.ts` по-прежнему видит `window.Telegram` при загрузке.
- `miniapp/Caddyfile` — `Cache-Control: public, max-age=31536000, immutable` для существующих файлов `/assets/*` (матчер `file`: на несуществующий путь отдаётся `index.html`, его кешировать нельзя).
- `screens/admin/*`, `screens/volunteer/History.tsx`, `Training.tsx` — `<h1>` заменены на `PageTitle`.
- `screens/volunteer/Me.tsx`, `screens/admin/Analytics.tsx` — UX-36, UX-40.
- Новых зависимостей и изменений контракта нет.

## Как проверить
- `cd miniapp && npm run build` — без ошибок; в `dist/assets` отдельные файлы `Summary-*.js`, `Analytics-*.js`, `CallScreen-*.js` и т. д.
- `VITE_MOCK=1 npm run dev`: `/`, `/me` на 390 px, вход координатора → переходы «Сводка → Поиск → База → Возможности → Аналитика → Настройки», карточки волонтёра и занятия, прямой заход на `/admin/analytics`. В сборке (`vite preview`) на главной грузятся только `index-*.js` и CSS, файлы кабинета — при входе в него.
- Без моков и без бэкенда (`npm run dev`, бэкенд не запущен): «Сервер сейчас не отвечает…»; без сети — «Нет связи с сервером…».
- После деплоя: `curl -I https://<домен>/assets/index-*.js` — есть `Cache-Control: public, max-age=31536000, immutable`.

## Что осталось и на что обратить внимание
- Caddyfile локально не запускал (нет Caddy/Docker) — проверить заголовок после деплоя командой выше.
- Шрифты Google Fonts по-прежнему подключены из CSS Google (по договорённости — без новых зависимостей); локальные шрифты дали бы ещё часть выигрыша по LCP.
- Основной файл всё ещё ~410 КБ: в нём моки (`mock.ts`) и экраны волонтёра — можно разбить отдельной задачей.
- Напарнику: на ожидаемые ошибки сервер должен отдавать `detail` по-русски — английский текст теперь заменяется общей фразой.

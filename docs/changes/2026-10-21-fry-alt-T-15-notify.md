# Волонтёру приходит сообщение в Telegram: «прошли обучение» и «вас допустили»

## Что изменилось
- Координатор ставит в карточке статус «допущен» (`approved`) → волонтёру в Telegram от бота: «Вас допустили к волонтёрству в фонде «Дети Марии»! 🎉 Откройте приложение — там задачи…».
- Волонтёр сдал все обязательные модули (`trained`) → «Вы прошли обучение — спасибо! 🎓 Координатор… скоро с вами свяжется».
- Пишем только тем, кто заполнил анкету из Mini App (там есть `telegram_id`), и только при смене статуса — повторное «допущен» второго сообщения не шлёт.
- Telegram недоступен или не принял сообщение (например, волонтёр не нажимал /start у бота) — статус всё равно сохраняется, ошибка только в логе. Таймаут 5 с.

## Где в коде
- Новый `backend/app/services/notify.py` — `status_changed(volunteer, old_status)`, тексты сообщений в `MESSAGES` (фонд может поправить их там).
- Вызов — в `services/volunteers.py::update` (координатор) и `services/training.py::update_status` (после теста).
- Использует уже существующий `TELEGRAM_BOT_TOKEN` (на проде он есть и у бэкенда). Новых переменных и зависимостей нет (`httpx` уже был), контракт не менялся.
- В логах — только id волонтёра и код ошибки: без текста сообщения, имени, контакта и токена (текст исключения httpx может содержать URL с токеном — его не пишем).
- `backend/tests/conftest.py` — autouse-фикстура `telegram`: во всех тестах вместо Bot API список отправленного, в настоящий Telegram тесты не ходят.

## Как проверить
- `make test` — `tests/test_notify.py` (допуск, повтор, без `telegram_id`/токена, Telegram недоступен, Telegram ответил 403, нет токена и ПД в логе) и `test_training.py::test_trained_volunteer_gets_telegram_message`.
- Руками проверено: живой бэкенд с неверным токеном → PATCH `approved` успешен, в логе «Telegram не принял сообщение волонтёру 1: 401».
- На проде после выкладки: заполнить анкету из бота @DetiMarii_bot → в `/admin` поставить «допущен» → сообщение в Telegram.

## Что осталось и на что обратить внимание
- Доставку настоящему пользователю не проверял — нужен боевой токен, он есть только на проде. Проверить по шагам выше перед демо.
- @gordeymos: для сцены (`docs/PITCH.md`) можно добавить шаг «координатор ставит „допущен“ → у волонтёра на телефоне сообщение».

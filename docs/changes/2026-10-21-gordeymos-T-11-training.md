# Экран обучения у волонтёра: модули, чтение, тест по одному вопросу, результат и статус

## Что изменилось
- `/training` — список модулей: «обязательный / по желанию», отметка «✓ Пройден · 92%», «Не сдан» или «Не начат»,
  сверху статус волонтёра и «Обязательных модулей пройдено: 2 из 3». После всех обязательных — «Обучение пройдено».
- Чтение модуля: markdown фонда показывается крупно (заголовки, абзацы, списки, цитаты, **жирный**), без новых библиотек.
- «Пройти тест» → понятный индикатор «Готовим вопросы…» (вопросы сочиняет LLM, 5–10 с) → вопросы по одному,
  крупные варианты, «Далее» / «← Предыдущий вопрос» → «Отправить ответы».
- Результат: балл, «Правильных ответов: 2 из 3», каждый ответ отмечен «✓ Верно» (зелёный) или «✗ Неверно» (красный)
  по `QuizResult.correct`, итоговый статус (`STATUS`). Не сдал — «Пройти тест ещё раз»; всегда — «Вернуться к модулям».
- Нет анкеты — экран предлагает заполнить `/form`; анкета не найдена — «Заполнить анкету заново». Ошибки — текстом
  из `errorText` с кнопкой повтора, выбранные ответы при ошибке отправки не теряются.

## Где в коде
- `miniapp/src/screens/volunteer/Training.tsx` — весь путь на состоянии экрана (список → чтение → тест), без новых маршрутов.
- `miniapp/src/screens/volunteer/training/Markdown.tsx` — простой рендер markdown (`#`–`###`, абзацы с переносами строк,
  `- ` и `1. ` списки, `> `, `**жирный**`).
- `.../training/QuizView.tsx` — загрузка теста, вопросы, отправка, разбор результата.
- `.../training/progress.ts` — отметки «пройден»/лучший балл по модулям в localStorage, ключ `training_progress_<volunteer_id>`.
  Контракт отдаёт только общий `training_score` и `status`, поэтому по-модульные отметки — подсказка на устройстве;
  допуск решает статус с сервера.
- `miniapp/src/mock.ts` — только блок обучения: модули как `data/training/*.md` (id `01-about`…, 3 обязательных + 1 по желанию,
  тексты сокращены), осмысленные вопросы; `quiz` отвечает за 4 с (как LLM); `submitQuiz` считает статус по всем
  обязательным модулям (лучший балл каждого ≥ 70% → `trained`), `training_score` — средний по обязательным.
- Контракт API, зависимости, `App.tsx`, `ui.tsx`, `labels.ts`, `api.ts`, admin — не менялись.

## Как проверить
1. `cd miniapp && VITE_MOCK=1 npm run dev`, заполнить анкету на `/form`, открыть `/training`.
2. Открыть модуль → «Пройти тест» → ответить с ошибкой: ошибочный ответ красный, балл < 70%, «Пройти тест ещё раз».
3. Пройти 3 обязательных модуля → статус «Обучение пройдено», в `/admin/volunteers/<id>` — тот же статус и балл.
Проверено руками на 375px и 320px (без горизонтальной прокрутки), сборка `npm run build` зелёная. Автотестов на фронте нет.

## Что осталось и на что обратить внимание
- Пункт Issue «балл в /admin» уже закрыт другими задачами: балл показывают карточки кандидатов (T-08) и карточка
  волонтёра (T-09, PR #38). Admin в этой задаче не трогал.
- Живой бэкенд обучения — T-10 (напарник). Экран ждёт контракт как есть: `GET /training`, `GET /training/{id}/quiz`,
  `POST /training/submit`; неотвеченный вопрос не отправляется (кнопка «Далее» неактивна).
- `request()` в `api.ts` для GET отдаёт в ошибке сырой текст ответа (например, `{"detail":"…"}`) — на живом бэкенде
  сообщение «не найдено» будет выглядеть как JSON. Это не моя зона в этой задаче; стоит поправить отдельно.

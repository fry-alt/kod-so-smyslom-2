# Умный поиск снова показывает кандидатов: экран больше не отсеивает всех сам

## Что изменилось
- Координатор искал по тексту или под роль и видел «Среди показанных кандидатов нет совпадений», хотя `POST /search` возвращал до 10 человек.
  Экран сразу повторно фильтровал ответ API (`matchesParsed`, T-119) и требовал **все** навыки из разбора целым словом — у ролей их 4–8.
  На 40 демо-анкетах под любую из 21 роли на экране оставалось 0. На `fake` текстовый поиск этого не показывал: разбор там пустой.
- Теперь до «Применить условия» показываем всех кандидатов от API — бэкенд их уже отфильтровал по времени, региону и формату.
- После «Применить условия» навыки — **любой** из списка, сравнение по первым 6 буквам и без разницы «е/ё», как `STEM` в `services/search.py`
  («фотография» ~ «фотографирую»). Ищем в навыках и интересах профиля и в ответах анкеты: навыки, о себе, опыт, пожелания.
- Анкеты без отмеченного формата и с регулярностью «как получится» не отсеиваются; «время от времени» подходит под «разово».

## Где в коде
- `miniapp/src/screens/admin/Search.tsx` — `activeParsed` теперь `null`, пока условия не применены; переписан `matchesParsed`.
  Контракт API не менялся.

## Как проверить
- `npm run build` в `miniapp` и `make lint && make test` — проходят.
- На 40 демо-анкетах (`fake`): до «Применить условия» видны все 7–10 кандидатов любой роли (было 0);
  после — от 0 до 9 в зависимости от роли, ноль — где в анкетах нет похожих слов («ярмарка», «маркетинг»).
- Руками: `/admin/search` → пример «Фотограф на четверг утром, разово» или роль из списка → карточки кандидатов на месте.

## Что осталось и на что обратить внимание
- «Применить условия» по-прежнему фильтрует только уже полученные 10 кандидатов, без нового запроса к API (ограничение из T-119).
- На проде с YandexGPT вживую не проверено — нужен вход координатора.

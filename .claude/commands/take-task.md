Работаем по [docs/WORKFLOW.md](../../docs/WORKFLOW.md). Аргумент: `$ARGUMENTS` — метка трека (`A` или `B`) или номер Issue.

1. `git checkout main && git pull`. Если есть незакоммиченные изменения — остановись и спроси пользователя.
2. Покажи, что нового у напарника: заметки в `docs/changes/` за последние 12 часов
   (`git log --since="12 hours ago" --name-only --format="%h %an %s" -- docs/changes/`) и `gh pr list --state open`.
   Прочитай новые заметки и перескажи в 2–3 строках.
3. Выбери задачу:
   - если передан номер — возьми его (проверь, что исполнителя нет или это `@me`);
   - иначе трек: если аргумента нет, определи по `gh api user -q .login` и таблице ролей в CLAUDE.md
     (fry-alt → `A`, gordeymos → `B`);
   - `gh issue list --label <трек> --state open --search "no:assignee sort:created-asc" --limit 10`,
     первым — `P0` из самого раннего открытого milestone; пропусти те, у которых «Зависит от» не закрыто
     (для трека B зависимость только от эндпоинта не блокирует — работаем на моках).
4. Покажи пользователю выбранную задачу (номер, заголовок, «Готово, когда») и сразу бронируй:
   `gh issue edit <N> --add-assignee @me`.
5. Создай ветку `a/T-NN-<коротко-латиницей>` или `b/T-NN-<коротко>` от свежего `main`.
6. Прочитай файлы из раздела «Где» в Issue и начинай работу по «Что сделать». Для нетривиальной задачи —
   сначала короткий план (3–6 пунктов) в чат.

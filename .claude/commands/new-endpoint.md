argument-hint: <метод путь — что делает, вход, выход>

Создай эндпоинт по описанию: $ARGUMENTS

Порядок:
1. Модели запроса/ответа — в `backend/app/schemas.py` (Pydantic v2, поля с понятными именами, ограничения через `Field`).
2. Логика — в `backend/app/services/` (новый модуль или существующий), без FastAPI-зависимостей, чтобы её можно было тестировать отдельно. LLM — только через `app.llm.client.get_llm()` (`chat` / `chat_json` / `embed`), промпты — через `load_prompt()` из `backend/app/llm/prompts/`.
3. Роутер — в `backend/app/api/<имя>.py` по образцу `api/case.py`; подключи его в `backend/app/main.py` (список модулей в конце файла).
4. Тест — `backend/tests/test_<имя>.py` через фикстуру `client` (провайдер `fake`, без сети): успешный сценарий + один негативный (422/400/404).
5. Если эндпоинт вызывает бот или Mini App — добавь метод в `bot/api_client.py` и/или `miniapp/src/api.ts` (типы синхронно со схемой).
6. Прогони `make test` и `make lint`, покажи результат.

Без новых зависимостей, без лишних абстракций. Ошибки LLM уже превращаются в 502 (`LLMError`), их не нужно ловить в эндпоинте.

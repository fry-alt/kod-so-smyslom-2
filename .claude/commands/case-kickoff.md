Прочитай `docs/CASE.md`, `CLAUDE.md`, `backend/app/schemas.py` и `backend/app/services/case.py`.
Дополнительный контекст от команды: $ARGUMENTS

Выдай ответ строго в таком виде, коротко:

1. **Минимальный сквозной сценарий** (5–7 шагов): что делает пользователь → что делает система → что видит жюри на демо. Один сценарий, без «а ещё можно».
2. **AI-блок**: какая именно задача решается LLM (классификация / извлечение / RAG-ответ / генерация), какой промпт нужен, откуда данные. Как измерим, что работает (метрика из CASE.md).
3. **Эндпоинты**: таблица `метод | путь | кто вызывает (бот / mini app / web) | что делает`. Переиспользуй существующие (`/chat`, `/documents/ask`, `/documents/upload`, `/case/run`), новые — только если без них никак.
4. **Контракт API**: Pydantic-модели запросов и ответов для новых/изменённых эндпоинтов (готовый код для `schemas.py` / `services/case.py`) + пример JSON запроса и ответа.
5. **Разбивка задач** на два параллельных трека, по 4–8 пунктов, каждый ≤ 1–2 часа:
   - **A (бэкенд и AI)**: `backend/`, `prompts/`, `data/`
   - **B (интерфейс и деплой)**: `bot/`, `miniapp/`, `web/`, Docker, сервер
   Первая задача у обоих — договориться о контракте из п.4; B до готовности бэкенда работает на провайдере `fake`.
6. **Риски** (не больше 3) и что делаем, если не успеваем.

Ничего не меняй в файлах, пока команда не подтвердит план.

## Как работаем — коротко (подробно в WORKFLOW.md)

1. **Начало сессии:** `git pull`, прочитай новые заметки в `docs/changes/` и открытые PR (`gh pr list`).
   Расскажи пользователю в 2–3 строках, что сделал напарник. Не переделывай чужое.
2. **Задачи — только GitHub Issues** с номером `T-NN` в заголовке. Бронь = исполнитель в Issue
   (`gh issue edit N --add-assignee @me`). Задачу с чужим исполнителем не бери. Быстро взять следующую — `/take-task`.
3. **Ветка на задачу:** `a/T-05-search` или `b/T-09-admin-search`. В `main` напрямую не пушим.
4. **Сдача:** проверка → заметка `docs/changes/ГГГГ-ММ-ДД-<логин>-<коротко>.md` по [шаблону](docs/changes/_TEMPLATE.md)
   → PR с `Closes #N` → зелёный CI → squash-мерж автором. Всё это делает `/finish-task`.
   PR без новой заметки в `docs/changes/` не проходит CI.
5. **Контракт API** (`backend/app/schemas.py` ↔ `miniapp/src/api.ts`) меняется только в одном PR с обеих сторон,
   и напарник отмечается в PR (`@` в описании) до мержа.

## Где что

- LLM — только через `app.llm.client.get_llm()`: `chat()`, `chat_json(prompt, Schema)` (валидация + 1 повтор), `stream()`, `embed()`. Провайдер — `LLM_PROVIDER` в `.env`.
- Промпты — `backend/app/llm/prompts/*.md`, переменные `$name`, загрузка `load_prompt("name", ...)`. В каждом промпте — пример (few-shot).
- Логика — `backend/app/services/`: `volunteers.py` (анкета → профиль → индекс), `search.py` (умный поиск), `training.py` (обучение и тест). HTTP — тонкие обёртки в `backend/app/api/`.
- Таблицы БД — `backend/app/models.py` (SQLModel). Роли фонда — `data/roles.json`, учебные тексты — `data/training/*.md`, демо-анкеты — `data/demo/volunteers.json`.
- RAG по документам фонда — `backend/app/rag/` (как в шаблоне).
- Фронт — `miniapp/src/`: экраны волонтёра (`/`) и кабинет фонда (`/admin`), клиент `api.ts`.
- Бот и фронт ходят **только в бэкенд по HTTP**, не в LLM напрямую.

## Принципы

- Главное — **умный поиск для координатора фонда**. Сначала он работает целиком на `fake`, потом подключаем реальный LLM.
- **Персональные данные** (имя, контакт, `telegram_id`) и заметки координатора **никогда не уходят в LLM и в векторный индекс** — только ответы анкеты и теги профиля. Так договорились с фондом (152-ФЗ).
- Любой вызов LLM — с фолбэком: поиск без LLM всё равно отдаёт кандидатов (по векторам и навыкам), анкета сохраняется, даже если профиль не извлёкся.
- Интерфейс — крупный шрифт, простые экраны, без жаргона: среди волонтёров пенсионеры, координатор не айтишник.
- Фонд будет сам поддерживать проект: простой код, понятный человеку, без лишних абстракций и магии.
- Никаких новых зависимостей без необходимости. Демо-данные — только вымышленные.
- Секреты — только в `.env` (он в `.gitignore`), никогда в коде и коммитах.
- Любой внешний вызов — с таймаутом и понятным сообщением об ошибке.
- Перед PR: `make lint && make test`. Новая логика в `services/` — с тестом в `backend/tests/`.
